# Transactional Ordering System

## Requirements & User Stories

## 1. Purpose

Build a backend system that reliably handles **orders, inventory reservation, and payments** under concurrent access, failures, retries, and timeouts.

The system must guarantee:

* No overselling
* Correct order state transitions
* Idempotent payment handling
* Automatic recovery from partial failures

This system must support **booking, e-commerce, and SaaS billing** use cases.

---

## 2. Actors

| Actor            | Description                          |
| ---------------- | ------------------------------------ |
| Customer         | Places and pays for orders           |
| Payment Provider | Sends asynchronous payment callbacks |
| Admin            | Monitors and manages orders          |
| System Worker    | Handles timeouts and retries         |

---

## 3. Core Concepts

### Order

A transactional entity with a **strict state machine**.

### Inventory

A limited resource that must be **reserved atomically** and **released automatically** if not paid.

### Payment

Asynchronous, retryable, and **idempotent**.
