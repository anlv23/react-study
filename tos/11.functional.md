## 6. Functional Requirements

### FR-1: Create Order

* The system shall create a new order with status `CREATED`.
* Each order has a unique ID.
* Orders are immutable except for status changes.

---

### FR-2: Reserve Inventory

* The system shall reserve inventory **atomically**.
* Reservation has a **TTL**.
* Reservation must be released if:

  * Payment fails
  * Order expires
  * Order is cancelled

---

### FR-3: Prevent Overselling

* Concurrent requests must not oversell inventory.
* Redis may be used for short-term locking.
* Database is the final source of truth.

---

### FR-4: Initiate Payment

* The system shall create a payment intent.
* Order status becomes `PAYMENT_PENDING`.
* Multiple payment attempts must not duplicate charges.

---

### FR-5: Handle Payment Webhooks

* Webhooks must be **idempotent**.
* Duplicate callbacks must not change final state.
* Payment success/failure must update order state correctly.

---

### FR-6: Order Timeout

* Orders not paid within a configured time must expire.
* Expired orders:

  * Release inventory
  * Transition to `EXPIRED`

---

### FR-7: Refund

* Paid orders can be refunded.
* Refund is idempotent.
* Refunded orders transition to `REFUNDED`.

---

### FR-8: Admin Access

* Admins can:

  * View orders
  * Filter by status
  * Manually cancel orders

---

## 8. Non-Functional Requirements

### Reliability

* Idempotent APIs
* Safe retries
* No partial state corruption

### Performance

* Inventory reservation < 100ms
* Supports high concurrency during spikes

### Consistency

* Database is the source of truth
* Redis failures must not corrupt data

### Observability

* Structured logs
* Correlation IDs
* Clear error messages

---

## 9. Failure Scenarios (Must Handle)

* Payment webhook called multiple times
* Server crash after inventory reservation
* Redis unavailable
* Worker delayed or retried
* Partial DB commit

---

## 10. Success Criteria

The system is considered complete when:

* No overselling is possible
* All state transitions are validated
* Payment retries are safe
* Timeout and recovery work automatically
