# TOÀN BỘ FLOW – TICKET BOOKING

(DB = PostgreSQL, Redis = lock + TTL)

---

## 0) Hệ thống khởi động

* Database chứa:

  ```
  seats: A1 = available
  ```
* Redis rỗng.
* Không có lock nào.

---

## 1) User mở app xem sơ đồ ghế

Backend query DB:

```
SELECT id, status FROM seats
```

DB trả:

```
A1 = available
A2 = booked
A3 = available
```

UI vẽ ghế.

**Redis không tham gia bước này.**

---

## 2) User click ghế A1

Backend thực hiện:

```
SET lock:seat:A1 order_101 NX EX 300
```

### Trường hợp A — Redis trả OK

→ Ghế được giữ tạm.

Backend tiếp tục update DB:

```
UPDATE seats
SET status='locked'
WHERE id='A1'
```

DB ghi nhận:

```
A1 = locked
```

Backend trả về:

"Bạn có 5 phút để thanh toán."

---

### Trường hợp B — Redis trả NULL

→ Ai đó đang giữ ghế.

Backend trả về:

"Ghế đang được giữ, chọn ghế khác."

DB không bị đụng tới.

---

## 3) Trong 5 phút giữ ghế

* Redis giữ key:

  ```
  lock:seat:A1 → order_101 (TTL đếm ngược)
  ```
* DB giữ:

  ```
  seats.A1 = locked
  orders.order_101 = pending
  ```

---

## 4) Nếu user thanh toán kịp

Backend xử lý thanh toán thành công.

Trước khi commit, backend kiểm tra:

```
redis.get(lock:seat:A1) == order_101 ?
```

Nếu đúng:

```
BEGIN

UPDATE seats SET status='booked' WHERE id='A1'
UPDATE orders SET status='paid' WHERE id='order_101'
DELETE lock:seat:A1

COMMIT
```

Kết quả:

* Redis không còn key
* DB:

  ```
  A1 = booked
  order_101 = paid
  ```

---

## 5) Nếu user bỏ ngang, không thanh toán

Sau 5 phút:

* Redis tự xoá key `lock:seat:A1`
* DB vẫn đang:

  ```
  A1 = locked
  order_101 = pending
  ```

Backend background worker phát hiện:

```
redis.get(lock:seat:A1) == null
```

→ rollback:

```
UPDATE seats SET status='available' WHERE id='A1'
UPDATE orders SET status='expired' WHERE id='order_101'
```

Kết quả:

* Redis: không key
* DB:

  ```
  A1 = available
  order_101 = expired
  ```

Ghế quay lại pool.

---

## 6) User khác giờ vào app

Query DB:

```
A1 = available
```

→ thấy ghế trống → có thể đặt.

---

# Tổng kết vai trò

| Thành phần | Làm gì                                |
| ---------- | ------------------------------------- |
| Redis      | Giữ lock tạm + TTL + chống tranh chấp |
| Database   | Lưu trạng thái chính thức ghế & đơn   |
| Backend    | Cầu nối điều phối giữa hai bên        |

---

# Nguyên tắc vàng

1. Không bao giờ đổi DB nếu chưa lock Redis thành công.
2. Redis hết TTL → backend rollback DB.
3. DB là source of truth cuối cùng.

---

# Chốt gọn 1 câu

> Redis giữ ghế tạm trong thời gian ngắn.
> Database ghi nhận kết quả cuối cùng.
> Backend đảm bảo hai bên luôn đồng bộ.

---

# Sơ đồ luồng ngắn

```
User → API → Redis SET NX EX
          ↓OK
        PostgreSQL update lock
          ↓
      Payment
   ↙ success      ↘ timeout
commit DB      Redis auto delete
delete key     worker rollback DB
```
