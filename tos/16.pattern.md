## 1️⃣ Pattern CỐT LÕI (bắt buộc phải biết)

### 🔑 **State Machine (Quan trọng nhất)**

Đơn hàng **không được nhảy trạng thái linh tinh**.

Ví dụ:

```
CREATED
→ INVENTORY_RESERVED
→ PAYMENT_PENDING
→ PAID
→ CONFIRMED
→ COMPLETED

Fail:
PAYMENT_FAILED
CANCELLED
EXPIRED
```

👉 Không có state machine = hệ thống rối

---

### 🔑 **Idempotency**

* Payment webhook gọi **n lần**
* Retry API

👉 Kết quả **chỉ xử lý 1 lần**

Cách làm:

* Idempotency key
* Check order state trước khi xử lý

---

### 🔑 **Inventory Reservation (Hold + TTL)**

* Giữ hàng / vé tạm thời
* TTL hết → release

👉 Redis + TTL rất hợp

---

### 🔑 **Atomic Operation**

* Trừ inventory
* Tạo order
* Set trạng thái

👉 DB transaction là hàng rào cuối

---

## 4️⃣ Pattern mày PHẢI THỂ HIỆN trong side project

✔ State machine rõ
✔ Redis hold + TTL
✔ Idempotency payment
✔ Timeout xử lý order treo
✔ DB là source of truth

---

## 5️⃣ Minimal architecture (chuẩn phỏng vấn)

```
API
 ├── Order Service
 │    ├── State Machine
 │    ├── DB Transaction
 │    └── Idempotency
 ├── Inventory (Redis + DB)
 ├── Payment (Webhook)
 └── Worker (Timeout / Retry)
```
