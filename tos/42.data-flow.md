
### State Transitions

```text
Inventory
──────────────
Initial:
available = 100
reserved  = 0

After reservation:
available = 99
reserved  = 1

After successful payment:
available = 99
reserved  = 0

OR

After reservation expires:
available = 100
reserved  = 0


Order
──────────────
PENDING_PAYMENT
        │
   ┌────┴────┐
   ▼         ▼
 PAID     EXPIRED


Reservation
──────────────
ACTIVE
  │
 ┌┴─────────┐
 ▼          ▼
COMPLETED RELEASED
```

This flow models a common production pattern because inventory is reserved immediately when the order is created, preventing overselling, and is either consumed on successful payment or returned to available stock when the reservation expires or is canceled.

## End-to-End User Flow (Flash Sale)

This flow describes everything that happens from the moment a user enters the flash sale page until the order is either paid or expires.

---

# 1. User Opens Flash Sale Page

### User Action

```text
GET /products/1
```

### Backend

```text
ProductService

↓

Read Product

↓

Read Inventory

↓

Return

- Product information
- Price
- Available quantity
- Flash sale status
```

### Response

```json
{
    "productId": 1,
    "name": "Mechanical Keyboard",
    "price": 49.99,
    "available": 100,
    "flashSale": true
}
```

---

# 2. User Clicks "Buy Now"

```text
User

↓

POST /orders

↓

OrderController

↓

OrderService.createOrder()
```

Request

```json
{
    "productId": 1,
    "quantity": 1
}
```

---

# 3. Validate Request

OrderService validates:

```text
✓ User exists

✓ Product exists

✓ Flash sale active

✓ Quantity > 0

✓ User purchase limit

✓ Product not disabled
```

If validation fails

```text
400 Bad Request
```

---

# 4. Start Database Transaction

```text
@Transactional
```

Everything below occurs in a single transaction.

---

# 5. Reserve Inventory

```text
InventoryService.reserve()
```

Current inventory

```text
available = 100

reserved = 0
```

Check

```text
available >= quantity ?
```

If not

```text
409 OUT_OF_STOCK
```

Otherwise

```text
available -= 1

reserved += 1
```

Inventory becomes

```text
available = 99

reserved = 1
```

---

# 6. Create Order

Insert

```text
Order

id = 5001

status = PENDING_PAYMENT
```

---

# 7. Create Reservation Record

Insert

```text
Reservation

orderId = 5001

productId = 1

quantity = 1

expiresAt = now + 10 minutes

status = ACTIVE
```

---

# 8. Commit Transaction

```text
COMMIT
```

Now

Inventory


Order

```text
PENDING_PAYMENT
```

Reservation

```text
ACTIVE
```

# Alternative Flow: Out of Stock

Current inventory

```text
available = 0
```

User

```text
POST /orders
```

Reservation check

```text
available >= quantity
```

Result

```text
false
```

Transaction

```text
ROLLBACK
```

Response

```http
409 Conflict
```

```json
{
    "error": "OUT_OF_STOCK"
}
```

No order is created and inventory remains unchanged.
